## 首帧等待的代码层问题

用户症状是等待首帧很久，点击停止时反而短暂出现画面。代码中找到的可解释路径包括：

1. 预览先预约视频源，并等待后台抓帧锁；后台若正阻塞于 OpenCV 打开或读取，预览尚未创建播放器便被拖住。
2. 预约已经可见、播放器尚未就绪时，分析端可能把空截图当作故障，转而启动独立解码器，延长同一把锁的占用。
3. Playing、Vout 和恢复流程可能并行执行就绪探测；旧流程反复覆盖启动遮罩，并将截图及尺寸探测作为显示前提。循环内等待累计超过名义上的 6 秒。
4. Vout 回调未区分输出数为零的停止事件和新视频输出；启动取消也被吞掉，调用方随后仍可能标记运行并连接分析。

这些是源码层已确认的时序问题；不能据此声称已复现用户这台设备上的完整故障。

## 修复后的启动和停止行为

- 视频源交接可取消。预览预约时取消进行中的后台抓帧，释放逻辑锁；取消后的原生打开结果由后台完成后自行释放，不能变成新的活动采集器。
- 预约中或播放器尚未 Playing 返回 Starting，分析不以此打开另一条竞争解码链。
- 同一播放器的就绪探测合并为一个任务；不再靠截图成功才能揭开视频遮罩。Playing 加有效视频输出或可用尺寸后，经过短暂 250 ms 缓冲显示视频。此时表示渲染面可显示，不代表完成 AI 分析，也不承诺摄像头端到端首帧为 250 ms。
- 忽略 Vout=0 以及旧播放器的回调；停止先隐藏并撤销旧视频宿主，避免拆卸时迟到的显示操作。
- 等待期间显示可用的停止按钮。停止使已排队的启动请求失效；旧任务不能在停止后重新连接安全监视器。
- 保留原有 1000 ms 网络缓存、预览迟帧恢复和主从每终端共享预览/分析的架构。没有把 RTSP 缓冲强行降为零。
- 记录视频输出显露耗时；日志不输出摄像头密码。

## 验证和现场验收

自动验证包含：编译、NUnit 回归、独立 DatasetSmoke、diff 检查。测试使用模拟服务、临时测试数据和本机回环 RTSP，不调用真实 AI、不连接真实摄像头、不操作屋顶或赤道仪。在线服务实测用例保持跳过。

Release 回归结果：248 项通过、0 项失败；3 项在线密钥测试跳过，另有 3 项标为 Explicit 的真实样例 API 测试未运行。Release 独立 DatasetSmoke 通过。运行中的 NINA 未被替换或重启，真实 RTSP 显示延迟尚未做现场验证。

新增预览回归覆盖：停止使旧及排队启动失效、Starting 不触发第二解码器、预约期间取消、后台打开被预览接管取消、原生打开超时、停止事件不作为 Playing、已取消连接不启动监控。安全回归覆盖新环境 AND、跟随从节点自身环境否决、主节点环境原因码、雨雾/Unknown 不等待二次确认、过期安全不被导星恢复和同毫秒留档不覆盖。

安装后仍需现场验证：

1. 正常启动预览，记录点击播放到可见画面，以及日志中的视频输出显露耗时；确认不必等待 AI 结果。
2. 启动中立即停止，确认停止按钮可操作，之后不自动重启预览或分析。
3. 快速切页、重新回到预览，确认不重复创建同源播放器；从节点跟随和接管分别验证。
4. 摄像头不可达时启动再停止，确认不会长期卡住 UI；恢复网络后检查自动恢复。
