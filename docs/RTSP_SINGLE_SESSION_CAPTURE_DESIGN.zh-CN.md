# AI Weather Advanced：RTSP 预览与分析单会话设计

## 1. 问题结论

异机诊断已经把故障定位到第二条 RTSP 客户端链路，而不是 Gemini、N.I.N.A. 安装或普通网络连通性：

- 同一地址通过 LibVLC 可以持续显示 3840×2160 预览；
- OpenCV/FFmpeg 的 `VideoCapture` 在初始化阶段立即返回 `IsOpened = false`；
- 失败发生在第一帧和 AI 请求之前；
- 关闭外部 OBS/VLC、移除 URL 末尾的 `?tcp` 均不能改变结果；
- 插件内原有的 LibVLC 预览与 OpenCV/FFmpeg 分析是两条独立 RTSP 会话。

因此，不应继续把“预览成功”与“分析抓帧成功”当作两个互不相关的条件。只要预览已经解码出画面，分析就应该复用这条已验证可用的链路。

## 2. 旧链路

```text
相机 RTSP
├─ LibVLC 会话 ──> N.I.N.A. 实时预览
└─ OpenCV/FFmpeg 会话 ──> AI 分析抓帧
```

这个结构会产生两个风险：

1. 相机、固件或客户端后端可能只允许其中一个会话稳定工作；
2. 预览明明正常，分析仍会因为另一套协议解析、鉴权或解码行为而永久拿不到第一帧。

## 3. 新链路

预览活动时改为单会话：

```text
相机 RTSP ──> LibVLC ──┬─> N.I.N.A. 实时预览
                       └─> 按需快照 ──> AI 分析
```

实现包含以下约束：

- 预览在打开 RTSP 前先登记其源地址并取得该地址的所有权；
- 安全监视器收到登记事件后，先释放同地址已有的 OpenCV 解码器；
- 后续天气检查从现有 LibVLC `MediaPlayer` 按需取得当前帧，不再建立第二条 RTSP 会话；
- 每次快照有独立临时文件、取消令牌和五秒总超时，完整载入内存后立即删除临时文件；
- 登记以去除 URL 用户信息后的端点标识进行匹配，日志只记录 SHA-256 短指纹，不写入用户名或密码。

## 4. 兼容路径

不能把 OpenCV 无条件删除，因为安全监视器可能在没有打开预览页的情况下后台运行。因此保留以下行为：

- **有同地址的活动预览：**只使用 LibVLC 当前帧；
- **活动预览暂时无法给出快照：**本次抓帧失败，禁止偷偷打开第二条 RTSP；
- **没有活动预览：**继续使用原有 OpenCV/FFmpeg 后台抓帧链路。

“活动预览无法给出快照”时返回空帧是有意的安全收口。上层监视器会按既有的陈旧/失联策略逐步转为不安全，而不会因为一次快照故障重新引入双会话冲突。

## 5. 生命周期与并发

- RTSP 分析操作由一个异步信号量串行化；
- 预览登记会等待旧分析解码器释放，但释放在后台线程执行，不阻塞 WPF UI；
- LibVLC 启动失败、最终未进入播放状态或启动被取消时，会清理失败播放器并撤销预览登记，使下一轮无头分析能够恢复 OpenCV 路径；
- 停止或重启预览时立即撤销登记，旧登记使用代际编号，不能误删新登记；
- 快照进行期间若预览被重启，所得旧帧会被丢弃并释放；
- 同一时刻只允许一次共享快照，避免 LibVLC 多个 `TakeSnapshot` 写入互相干扰。

## 6. 验证范围

自动化 smoke 测试覆盖：

1. 用户名或密码不同但端点相同，仍识别为同一视频源；
2. RTSP 路径不同，不会错误复用另一画面；
3. 活动预览成功提供帧时，OpenCV 初始化和抓帧调用次数均为零；
4. 活动预览快照失败时，也不会创建第二条 RTSP；
5. 没有预览登记时，原有后台分析抓帧仍正常工作；
6. 登记释放后不会留下失效回调。

项目 Release 编译与完整 `AIWeather.DatasetSmoke` 已通过。最终还应在出现问题的异机上做一次真实相机验证，确认日志出现“从现有 LibVLC 预览取得分析帧”，并且不再出现 OpenCV 初始化第二会话的记录。
