# AI Weather Advanced 高可用本地接管设计

状态：**v1 已实现并通过本地集成测试**
日期：2026-08-28
适用项目：`nina.plugin.aiweather-advanced`

## 1. 问题与目标

旧版主从模式只有一条安全判断链路：

```text
全天相机 → AI Weather 主节点 → 局域网 → AI Weather 从节点 → N.I.N.A. Safety Monitor
```

主节点进程、主节点电脑或主从网络任一点失效，从节点都会按设计进入 Unsafe。故障安全是正确的，但可用性较差；远程台可能因此在天气仍可观测时失去全部天气判断能力。

本设计给 AI Weather 增加**固定优先级的自动本地接管**：

- 正常时从节点仍只读取主节点状态，不重复占用相机和在线 API。
- 主节点连续不可达达到设定时间后，从节点使用事先同步并验证过的配置，在本机启动相机采集和天气分析。
- 主节点恢复后必须持续稳定达到回切时间，从节点才停止本地采集并恢复远程状态。
- 本地接管开始、第一次有效分析之前始终 Unsafe；任何未知状态都不继承旧 Safe。

这不是无中心共识或自动选主。系统仍有明确的首选主节点，只为每个从节点增加本地生存能力，避免引入选举脑裂和多写者复杂度。

## 2. 明确不做的事情

1. 不给 RRCI 屋顶控制增加自动硬件接管。天气读取允许短暂双读；屋顶驱动双写可能造成真实机械危险，两者不能类比。
2. 不在主节点断线后把从节点广播成新的网络主节点。其他从节点仍按各自策略本地接管；v1 不做发现、仲裁或浮动 IP。
3. 不同步数据集路径、人工复核状态、安全状态输出文件或本机外部 ASCOM 安全监视器配置。
4. 不把在线模型、全天相机或软件安全监视器宣传为独立的最终安全设施。雨量计、物理限位、防撞、断电收顶等保护仍不可替代。

## 3. 运行状态机

```text
RemoteWaiting / RemoteSynchronized
       │
       │ 连续 Network/Timeout，达到 failover-after
       │ 且存在可解密、可验证的本地接管配置
       ▼
LocalStarting（强制 Unsafe）
       │
       │ 相机成功取帧且分析成功
       ▼
LocalFailover（按本地新鲜度、云量、雨雾、太阳高度和外部监视器判定）
       │
       │ 主节点重新可认证通信，并持续稳定达到 recovery-stable
       ▼
RemoteSynchronized
```

### 3.1 触发接管

- 只把网络不可达、连接超时、主节点进程退出视为自动接管候选。
- 共享令牌错误、请求签名错误、协议版本不兼容属于配置或安全故障，**不得**自动接管以掩盖问题。
- 默认失联接管时间 60 秒，可配置为 15–3600 秒。
- 失联后先按现有传输新鲜度阈值变为 Unsafe，再启动本地分析；不会用旧主节点 Safe 填补空窗。
- 没有同步配置、缓存无法解密或本地相机配置无效时保持 Unsafe，并给出明确原因。

### 3.2 本地接管

- 接管只在当前 N.I.N.A. Safety Monitor 已连接期间有效。
- 本地接管复用现有 `UnifiedCaptureService`、分析编排器、云量迟滞、太阳高度门和数据新鲜度逻辑。
- 从节点的本地外部 ASCOM 安全监视器继续与天气结果做 AND，只能收紧结果。
- 接管期间不写教师—学生数据集，避免主节点恢复前后出现不受控的双数据集写入。
- 接管期间按正常天气检查间隔分析，不按数秒级网络轮询间隔调用在线 API。

### 3.3 恢复回切

- 任意一次通过认证的有效状态响应都证明主节点进程重新可达；天气本身 Unsafe 不会阻止回切。
- 默认要求主节点连续稳定 30 秒，可配置为 5–600 秒。
- 稳定期内从节点继续使用本地结果，避免网络抖动造成相机和模型反复启停。
- 回切时先停止本地采集，再应用最新远程状态；若远程状态不新鲜则仍为 Unsafe。

## 4. 配置同步范围

允许同步的接管配置：

- 采集模式、RTSP/HTTP/文件夹地址、相机用户名与密码；
- 分析提供商、模型、Gemini/OpenAI/Anthropic/GitHub Models 凭据；
- Ollama 地址和思考开关；
- 检查间隔、最大数据年龄、太阳高度门、云量高低阈值。

明确不包含：

- 集群角色、主节点 URL、监听端口和共享令牌本身；
- 数据集、复核器和调试图片目录；
- 本机外部 ASCOM 安全监视器；
- 安全状态文件路径和其他机器专属路径。

主节点和从节点都必须显式打开“故障转移配置同步”。主节点不开启时不提供配置端点；从节点不开启时不请求配置。自动接管也单独开关，默认关闭，避免普通状态从节点在升级后悄然获得和使用主节点秘密。

## 5. 局域网认证升级

旧协议使用：

```http
Authorization: Bearer <shared-token>
```

Bearer 会把令牌直接放入明文 HTTP。新协议改为每次请求的 HMAC-SHA256 签名：

```text
HMAC(shared-token,
     protocol-version + method + path + unix-time + node-id + random-nonce)
```

请求携带时间、节点 ID、随机 nonce 和签名，但不携带共享令牌。服务端执行：

- 固定时间签名比较；
- 时间窗口检查；
- nonce 有界重放缓存；
- 固定方法和路径、有限请求头大小。

协议 schema 从 1 升为 2。新旧节点混用时必须故障安全地认证失败，直到两边都升级。

HMAC 只提供身份认证和请求完整性，不会加密普通天气状态。端口仍应由 Windows 防火墙限制到受信任从节点；公网必须走 VPN/TLS。

## 6. 凭据传输与缓存

配置正文用 AES-256-GCM 加密：

- 密钥由共享令牌和随机 salt 使用 PBKDF2-SHA256 派生；
- 每个响应使用随机 GCM nonce；
- schema、产品、主节点 ID、主节点 session、配置修订号和生成时间作为附加认证数据；
- 配置修订号为共享令牌参与的 HMAC 摘要，不公开可离线猜测的普通 SHA-256。

从节点只把收到的**加密信封**写入插件设置；明文 API/相机凭据不写入从节点普通设置，也不写日志。启动时使用当前共享令牌解密缓存；令牌变化、信封篡改、产品或 schema 不匹配都会使缓存失效并保持 Unsafe。

### 6.1 从节点设置页的可观察性

同步开启时，不能继续把从节点本机设置画成“可编辑且像是会生效”的普通字段。设置页改为显示一个明确标注为“主节点同步的接管配置（只读）”的安全投影，包含配置修订、最近同步时间、采集模式、脱敏后的来源、检查间隔、太阳高度门、云量高低阈值、最大数据年龄、AI 提供商、模型和凭据是否已配置。RTSP 用户信息、URL 查询中的密钥、相机密码及 API 密钥永不进入这个投影，只显示“已配置并加密同步（内容隐藏）”。

正常联机期间，从节点使用的仍是主节点发布的最终安全结论；这个只读面板描述的是主节点失联后本机接管所使用的缓存配置。关闭同步时，只读面板消失，本机备用字段恢复可编辑，且运行时必须忽略旧同步缓存，避免“界面看起来已改、本地接管仍暗中使用旧值”。

## 7. 配置项

| 配置 | 默认值 | 范围 | 用途 |
|---|---:|---:|---|
| 自动本地接管 | 关闭 | 开/关 | 仅从节点使用 |
| 失联后接管 | 60 秒 | 15–3600 秒 | 网络连续不可达多久后启动本地分析 |
| 恢复稳定时间 | 30 秒 | 5–600 秒 | 主节点恢复多久后回切 |
| 加密配置同步 | 关闭 | 开/关 | 主节点授权导出、从节点授权接收 |
| 加密配置缓存 | 空 | 内部 | UI 只显示无秘密的只读投影；不显示或记录密文/明文凭据 |

## 8. 安全不变量

1. 接管前、切换中和第一次有效本地分析前一律 Unsafe。
2. 远程旧 Safe 不得带入本地接管；本地旧 Safe 不得带回远程模式。
3. 认证/协议错误不触发接管。
4. 本地接管没有有效配置或初始化失败时不反复高频重试相机/API，也不变 Safe。
5. 主节点恢复稳定前不回切，避免状态抖动。
6. 日志只写配置修订号、状态和错误类别，不写 URL 用户信息、相机密码、API 密钥、共享令牌、密文或派生材料。
7. 插件断开、卸载或 N.I.N.A. 退出时停止远程轮询和本地接管，清除运行期 Safe。

## 9. 测试与验收

- HMAC 正确请求成功；错误令牌、路径篡改、过期时间和 nonce 重放均失败。
- AES-GCM 配置可往返；错误令牌、密文或标签篡改均无法解密。
- 配置修订变化后只同步一次；缓存重载仍可接管。
- 只读配置投影不包含相机密码、RTSP 用户信息、URL 查询密钥、API 密钥或共享令牌。
- 关闭同步后旧缓存不再覆盖界面显示的本机备用配置。
- 网络短暂抖动不接管；达到阈值才接管。
- 认证/协议错误始终 Unsafe 且不接管。
- 接管后第一次有效分析之前 Unsafe。
- 主节点短暂恢复不回切；持续稳定达到阈值后回切。
- 接管期间网络仍持续探测，在线分析遵循分钟级检查间隔而非秒级轮询间隔。
- 独立模式、主节点模式和未启用自动接管的旧从节点行为不回归。

## 10. 部署顺序

1. 先升级主节点插件；旧从节点会安全地认证失败。
2. 在主节点启用加密配置同步。
3. 升级从节点，启用配置同步并先成功连接主节点一次，使加密缓存落盘。
4. 在从节点启用自动本地接管。
5. 有人值守时模拟停止主节点服务，验证从节点先 Unsafe、后本地接管；恢复主节点并验证延迟回切。

未经双机验证前，本功能只能视为提高软件可用性的附加层，不是无人值守台的唯一气象安全依据。
