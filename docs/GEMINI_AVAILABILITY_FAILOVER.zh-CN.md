# Gemini 付费/免费策略与可用性设计

## 1. 为什么拆成两个选项

Google Gemini 免费层在现场运行中会同时受到每日额度、每分钟额度、模型局部过载和版本可用性影响。此前插件把“用户选定模型”“同系列临时切换”“重试”和配额熔断揉在同一个 `Gemini` 选项里，行为不够可预测：界面显示的是一个模型，真正请求的却可能已经换到另一个模型。

现在插件把它们拆成两个明确的操作策略：

| 选项 | 面向场景 | 模型行为 |
|---|---|---|
| `Gemini` | 已启用结算、希望严格控制模型的项目 | 只调用用户选定模型；一次分析只发送一次请求；不排序、不降级、不切换、不重试、不退避 |
| `Gemini 免费` | 免费层、优先争取在线可用性的项目 | 按用户可调整的顺序遍历模型池；每个模型一次；完整模型池可循环多轮 |

两者仍使用 Google Gemini Developer API，但在插件中拥有独立 API Key、独立调用比例、独立配置和独立诊断来源。插件中的“付费/免费”是操作员选择的策略与凭据槽位；真实限额仍由 API Key 所属的 Google 项目决定。

旧版唯一的 `Gemini` 选项在界面和文档中明确写作免费层。因此升级后只执行一次迁移，把旧选择、旧 `GeminiKey` 和旧调用比例保留到 `Gemini 免费`；迁移标记写入后不会再次擅自改变用户后来选择的付费 `Gemini`。

## 2. 普通 Gemini：严格单模型

普通 `Gemini` 的生产行为固定为：

1. 使用单独的付费项目 API Key；
2. 使用模型下拉框中用户明确选定的一个模型；
3. 每次需要在线分析时只发送一个 HTTP 请求；
4. 无论收到 `503`、超时、网络错误、认证错误、Schema 错误还是配额错误，都不请求第二个模型；
5. 不保存模型排序状态，不使用备用模型，不把任何模型写回或替换用户选择；
6. 仍保留请求超时、精确 HTTP 状态、失败分类、模型名和耗时诊断；
7. 不打开跨检查配额熔断或退避状态；下一次满足用户调用比例的天气检查仍只请求同一个选定模型。

这意味着普通 `Gemini` 的界面和真实请求完全一致：选中哪个模型，插件就只请求哪个模型。

## 3. Gemini 免费：有序模型池

免费选项不显示单模型下拉框，而显示一个可滚动、可上移、可下移、可恢复默认的模型列表。默认顺序为：

1. `gemini-3.5-flash-lite`
2. `gemini-3.1-flash-lite`
3. `gemini-3.7-flash`
4. `gemini-3.6-flash`
5. `gemini-3.5-flash`
6. `gemini-3-flash`
7. `gemini-2.5-flash`
8. `gemini-2.0-flash`
9. `gemini-2.5-flash-lite`
10. `gemini-2.0-flash-lite`

“完整轮询次数”默认是 `2`，范围为 `1–10`。一次在线分析按如下方式执行：

```text
第 1 轮：模型 1 → 模型 2 → … → 模型 10
第 2 轮：模型 1 → 模型 2 → … → 模型 10
任一模型成功：立即返回在线结果
全部配置轮次无成功：返回一次明确的在线失败，由编排层执行显式本地回退
```

模型池顺序是可调整但不可删除的。升级加入新默认模型时，会把缺失的新模型追加到用户既有顺序末尾，避免旧配置永久失去新的可用候选。

## 4. 每模型配额状态机

免费池中的每个精确模型都拥有独立配额熔断状态，键由 API Key 的非明文指纹与模型名组成：

- 某模型返回结构化 `429/QuotaFailure` 后，只暂停该模型；
- 后续遍历遇到仍处于暂停期的模型时直接跳过，不发 HTTP 请求；
- 其他模型继续按列表顺序尝试；
- 到达服务端允许的重试时间后，该模型重新进入正常遍历；
- 每日额度和短周期额度继续保留各自的重试时间语义；
- 状态机不记录 API Key 明文。

免费池策略确实可能消耗同一项目下多个模型的免费额度，这是该独立选项的显式设计。普通 `Gemini` 永远不采用此策略。

## 5. 调用节流与耗时边界

两个选项分别拥有“每 N 次天气检查运行一次”的设置。计划性跳过只影响在线教师，本地安全分析、相机抓帧和结果新鲜度仍按正常天气检查运行。

免费池中每个模型请求有独立的 20 秒上限。最坏耗时由“模型数量 × 完整轮数 × 单模型上限”决定；默认 10 个模型、2 轮的理论极端上限较长，但通常会因模型成功、明确 HTTP 失败或配额跳过而提前结束。用户可以把完整轮数降为 1 来缩短最坏等待时间。

普通 `Gemini` 仍只有一个请求窗口，不会因任何自动重试扩张为多个模型的等待链。

## 6. 诊断与回退语义

每次真实请求或配额跳过都写入非敏感诊断：

- 池中位置/尝试序号；
- 精确模型名；
- HTTP 状态（若收到响应）；
- 稳定失败分类；
- 请求耗时；
- `success`、`http_error`、`quota_rejected`、`network_error`、`timeout` 或 `quota_circuit_skipped`。

不保存响应正文、API Key、相机密码、图片或代理凭据。免费池最终失败优先保留最具体的服务端证据，避免后续的通用超时遮住较早的 `503`。

运行时显示和数据集来源会明确区分 `Gemini` 与 `Gemini Free`。在线失败后的 ONNX 结果仍标记为显式本地回退，不能伪装成成功在线教师标签。

## 7. 主节点/从节点同步

启用加密接管配置同步时，主节点会同步：

- 当前选择的是普通 `Gemini` 还是 `Gemini 免费`；
- 对应策略自己的 API Key；
- 普通 Gemini 的单模型与调用比例；
- 免费 Gemini 的模型顺序、完整轮数与调用比例。

凭据继续只存在于 AES-256-GCM 加密配置中；只读摘要仅显示“已配置/未配置”，不显示明文。接管节点因此能复现主节点的同一策略，而不会把普通 Gemini 的单模型配置误解释为免费池。

## 8. 回归验收

自动测试至少覆盖：

1. 普通 `Gemini` 的选定模型返回 `503` 时只出现一次请求，预置的备用模型绝不被访问；
2. 普通 `Gemini` 的失败保留精确 `503`，不变成未知错误；
3. 免费池严格按配置顺序在第一个成功模型处停止；
4. 处于配额暂停期的模型被跳过且不发 HTTP 请求；
5. 所有模型都失败时，严格完成配置的全部轮次后才返回失败；
6. 默认顺序、默认两轮、一次性旧配置迁移以及加密主从配置同步保持稳定。
